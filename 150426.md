## 3. Trạng thái production (lần check gần nhất)

`GET https://adative-math-coach.vercel.app/api/health` trả về dạng:

```json
{
  "ok": false,
  "env": {
    "hasOpenAiKey": false,
    "acceptsUserApiKey": true,
    "hasDatabaseUrl": true,
    "sessionStore": "supabase",
    "dbOk": false,
    "onVercel": true
  },
  "data": {
    "mathIndexExists": true,
    "nodesExists": false
  }
}
```

| Ý nghĩa | |
|---------|--|
| UI + math-index | OK |
| User dán OpenAI key | OK (`acceptsUserApiKey`) |
| Env DB có | OK (`hasDatabaseUrl`) |
| **`dbOk: false`** | **Postgres `select 1` fail** — chưa connect được (pooler/password/SSL/project pause/…) |
| `nodes.jsonl` missing | Bình thường trên Vercel (chỉ deploy indexes) |

**Lỗi user từng gặp:**  
`ENOENT: mkdir '.../data/sessions'` — vì trước đó store local-fs trên serverless. Code mới: Postgres trước; không mkdir project root trên Vercel.

**Cho đến khi `dbOk: true`:** Submit diagnostic có thể vẫn lỗi save session.

## 4. Việc Grok Bot / agent tiếp theo nên làm

### P0 — Sửa DB connection (blocking prod)
1. Verify Supabase **erin-forest** Active (không Paused)
2. Confirm SQL đã chạy: tables `amc_sessions`, `amc_learners`, `amc_events`
3. Debug `dbOk: false`:
   - Dùng **Transaction pooler** URI port **6543**
   - Encode password đặc biệt trong URL
   - SSL: code đang `rejectUnauthorized: false` non-localhost
   - Log lỗi thật từ `dbQuery("select 1")` vào health response (tạm `dbError` message, không leak password)
4. Redeploy → health: `dbOk: true`, `ok: true`
5. E2E: diagnostic Submit → row trong `amc_sessions`

### P1 — Harden
- Health: tách `okContent` vs `okDb` rõ hơn
- Rate-limit learner PIN
- Không log header `x-openai-api-key`

### P2 — Product (từ Future feature)
- Supabase full content ETL + `/admin`
- Jurisdiction rebuild đã partial; deepen
- Git LFS cho `math-index.json` (~79MB warning)

### P3 — Không ưu tiên
- Neo4j
- ELA coach (trừ khi product yêu cầu)
- Lưu API key user trên server/DB
